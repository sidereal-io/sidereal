## 2. Core runs, records previews and lists originals [depends-on: 1]

- [ ] 2.1 [medium] `run_operator` reads the version's media type and its Asset's `origin`, and returns the new `RunOutcome::NotAccepted`, before it inserts a run row, when the Asset is derived or the Operator does not accept the media type. - [ ] 2.2 [complex] `run_operator` gives the Operator a staging `Output` that begins staging on the first write, then checks, publishes and commits a proposed preview in `store`'s transaction: a new Asset with `origin` `derived`, the proposed kind and the input Asset's name; its version with core's BLAKE3 hash and size, the proposed media type and the Operator's id and version as `source_id` and `source_version`; and one `asset_lineage` row with role `preview` and the run's id. New tests in `core/src/operations/derives.rs`, using `fixture.rs` and `Scripted` Operators with `makes_previews`, cover every scenario of derived-assets "Core checks a proposed preview before it stores it", "Core records a preview as a derived asset with lineage", "A preview commits with its run", "A failed write invalidates the preview", "Cancellation before the preview transaction stops the run" and "A refused proposal stores nothing from the run", with these reasons: `operator <id> does not make previews`, `a preview cannot be image/tiff`, `the preview is empty`, `the preview is larger than 100 MiB`; each failure leaves no new Asset, version, lineage row or file in the storage folder's `tmp`, and a refused facet stores neither the facet nor the preview. ## 3. The image pack: one module per format, TIFF and previews [depends-on: 1]

- [ ] 3.1 [complex] The image pack has the layout of design decision 6, for PNG and JPEG, with no change in what they record: `io.rs` holds `CandidateReader`, which records a failed read, and `head(context, len)`; `formats/mod.rs` holds the internal `ImageFormat` trait, the `FORMATS` table and `probe_len()`, `recognize()`, `by_media_type()`, `media_types()` and `refusal()`; `formats/png.rs` and `formats/jpeg.rs` hold each format's signature, probe length, media type and `dimensions`, the JPEG module its 8 MiB read limit. The Source reads `probe_len()` bytes; the pack's public `unsupported()` replaces `UNSUPPORTED`; the file-size and header Operators accept `media_types()`. `header.rs` picks the format by `context.media_type()` and fails with `the stored file could not be read` after any failed read. `src/testing.rs` installs the counting allocator for the pack's unit tests only, and the memory and 8 MiB read-limit tests move from `tests/memory.rs` and `tests/header.rs` into `#[cfg(test)]` modules in `png.rs` and `jpeg.rs`; `tests/memory.rs` is removed. Tests written first: a unit test in `formats/mod.rs` that no two formats share a media type or match each other's signature, and that `refusal()` reads `only PNG and JPEG images are supported`; the pack scenario of asset-facets "An Operator declares the media types it accepts", for PNG and JPEG; asset-facets "The media type decides how the header is read" and "A later read fails"; `tests/header.rs` and `tests/recognition.rs` pass each run's media type and still pass (design decision 6; brainstorm D13, D15) (verify: `cd server && cargo test -p sidereal-pack-image --lib`, then `cargo test -p sidereal-pack-image`)
- [ ] 3.2 [complex] `formats/tiff.rs` adds TIFF as one module and one `FORMATS` entry: name `TIFF`, media type `image/tiff`, a 4-byte probe and the signatures `II*\0`, `MM\0*`, `II+\0` and `MM\0+`; `dimensions` reads the first image's width and length through the private directory reader `tiff/ifd.rs` (classic and BigTIFF, both byte orders, at most 4,096 entries). The dimension read skips every value except width and height, including unrelated arrays beyond the preview reader’s limits. The refusal now reads `only PNG, JPEG and TIFF images are supported`, and every Operator of the pack accepts `image/tiff`, with no other source file changed for it. Tests in `packs/image/tests/recognition.rs` cover the four signatures and the refusals for GIF, SVG, empty bytes and plain text; new tests in `packs/image/tests/tiff_header.rs` cover every scenario of asset-facets "The header Operator reads a TIFF's first image" and "A TIFF header that cannot be read fails the header run"; unit tests in `tiff.rs` cover the directory's entry and value-array caps; the `formats` and pack-registration tests now expect three formats (design decision 7; image-upload "Image recognition uses the bytes") (verify: `cd server && cargo test -p sidereal-pack-image --test tiff_header`, then `cargo test -p sidereal-pack-image`)
- [ ] 3.3 [complex] The image pack registers `image.make-preview` (`MAKE_PREVIEW`), which makes previews, lists no facets, accepts `media_types()` and proposes kind `image` and media type `image/jpeg`. `preview.rs` holds the shared `Pixels` buffer, the side check (65,500) and the peak decode budget check (536,870,912 bytes, including scratch), the row-by-row `ImageBuffer` and the quality-90 baseline 4:4:4 `jpeg-encoder` stream in chunks of at most 64 KiB to `write_preview`. `render_preview` in `png.rs` decodes with `png` (`EXPAND`, 16-bit kept), and in `jpeg.rs` with zune-jpeg, with explicit decoder dimensions and strict mode. Its marker walk and header parsing use the 8 MiB limit, then the strict pixel decode reads the full file. Each format computes its documented allocation bound and runs both checks before decoding. Tests in `packs/image/tests/preview.rs` run `Registry::execute_operator` with a media type and a collecting `Output`, decode the preview, and cover the image-preview scenarios for PNG and JPEG: registration, same size, EXIF rotation ignored, progressive JPEG, an image larger than the JPEG header read limit, truncated progressive scan data, the transparent PNG pixel within 8, the PNG and JPEG memory-limit failures, the PNG and JPEG decode failures, and the failed read; the unit tests of `png.rs` and `jpeg.rs` gain the preview memory cases for an RGBA PNG and a progressive JPEG, each at most the calculated peak bound within the 512 MiB budget (design decision 8; image-preview "The image pack registers a preview Operator", "A preview is an 8-bit JPEG of the whole image", "The preview Operator decodes PNG, JPEG and TIFF", "A transparent pixel shows over black", "A damaged image fails the preview run", "A preview's sides fit a JPEG", "A preview decode needs at most 512 MiB") (verify: `cd server && cargo test -p sidereal-pack-image --test preview`, then `cargo test -p sidereal-pack-image --lib`, then `mise run check-server`)
- [ ] 3.4 [complex] `render_preview` in `tiff.rs` makes previews of TIFF: it refuses with `the TIFF image type is not supported`, before decoding, every first image the spec does not list (CMYK, an alpha sample, JPEG compression, white-is-zero, planar samples, other sample sizes), runs the side and memory checks, and decodes with `tiff` (no default features, `lzw` and `deflate`) with limits derived from its documented peak estimate. Preflight checks first-IFD array sizes, compatible unsigned or floating-point sample and predictor combinations, strip and tile layout and padded floating-point scratch before it reads pixels. 16-bit samples become `v × 255 / 65535` rounded, decimals are clipped to 0–1 with not-a-number as 0, and a grayscale TIFF gives a one-component JPEG. Tests in `packs/image/tests/preview.rs` cover every TIFF scenario of image-preview, including the BigTIFF big-endian Deflate file, the tiled LZW file with a predictor, the several-images file, the 16-bit and decimal pixel values within 8, both browser JPEG side limits, a header-only case whose pixels alone need 512 MiB, oversized tile scratch without any pixel read, a passing floating-point padded tile, a signed 16-bit refusal, and the 15,000 by 6,000 16-bit file failing on memory with no pixel read, and the PNG bytes stored as `image/tiff`. The unit tests of `tiff.rs` gain the preview memory case for a 16-bit RGB TIFF, at most the calculated peak bound within the 512 MiB budget (design decision 8 and its first risk; image-preview "The preview Operator decodes these TIFF types", "Sample values are scaled to 8-bit with no brightening", "A TIFF of another type fails the preview run", "A preview's sides fit a JPEG", "A damaged image fails the preview run") (verify: `cd server && cargo test -p sidereal-pack-image --test preview tiff`, then `cargo test -p sidereal-pack-image --lib`, then `mise run check-server`)
