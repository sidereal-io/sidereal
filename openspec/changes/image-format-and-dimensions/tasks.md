## 3. The image pack's header Operator [depends-on: 1]

- [ ] 3.1 [easy] The image pack declares `image.format` (label `Format`, `FacetType::Choice` of `PNG` and `JPEG`, unit `""`), `image.width` and `image.height` (labels `Width` and `Height`, `FacetType::Count`, unit `pixels`), each at version 1 and `FacetScope::AssetVersion`, and registers the Operator `image.read-header` at the pack's version, listing exactly those three facets; the Source and the new Operator share one signature check; the constants are public, as `FILE_SIZE` is (design decision 5; asset-facets "The image pack declares the format and pixel dimension facets") (verify: `cd server && deli -- cargo test -p sidereal-pack-image --test header schema`)
- [ ] 3.2 [medium] `image.read-header` run through `Registry::execute_operator` over in-memory bytes proposes `image.format` `PNG`, `image.width` 4096 and `image.height` 2160 for a PNG whose `IHDR` gives 4,096 by 2,160; it fails with `the PNG header could not be read` for the 8-byte signature alone, for a first chunk other than a 13-byte `IHDR`, and for a width or height of 0 or above 2,147,483,647; and fails with `the image format is not recognized` for bytes that start with neither signature (design decision 5; asset-facets "The image pack records an image's format and pixel dimensions" PNG scenario, "A header that cannot be read fails the header run") (verify: `cd server && deli -- cargo test -p sidereal-pack-image --test header png`)
- [ ] 3.3 [complex] `image.read-header` walks JPEG markers without reading segment bodies and proposes `JPEG` with the frame header's width and height for: a baseline (`0xC0`) JPEG of 6,000 by 4,000; a progressive (`0xC2`) JPEG of 1,920 by 1,080; a JPEG with a 60,000-byte `APP1` EXIF segment and an `APP2` ICC segment before its frame header; a JPEG whose EXIF orientation says to rotate 90 degrees, which still gives 6000 by 4000; and `0xFF` fill bytes before a marker. It fails with `the JPEG header could not be read` when it reaches start-of-scan or end-of-image before a frame header, when the bytes end inside a segment, at a byte that is not a marker, at a segment length below 2, and for a width or height of 0. A test candidate that counts reads shows that the 60,000-byte segment costs one read, and a run whose host reports cancellation stops the walk (design decision 5; asset-facets "The image pack records an image's format and pixel dimensions" JPEG scenarios, "A header that cannot be read fails the header run") (verify: `cd server && deli -- cargo test -p sidereal-pack-image --test header jpeg`)

## 4. Upload runs the header Operator [depends-on: 2, 3]

- [ ] 4.1 [complex] `Library::new` runs `[FILE_SIZE, READ_HEADER]` over each new version, and `save` logs `<operator id> run failed for asset <id>: <reason>` and `<operator id> run not recorded for asset <id>: <error>`.
