## Deviations Ledger

- **2026-11-25, after the pull request review: section 7 added.** The user
  dropped the `image.format` facet and the choice type. The entries below on
  2.1 (allowed values in the new schema row) and on a refused choice's
  reason stop applying once 7.3 and 7.4 are built. The entries on the PNG
  limit and on `CandidateReader::read` still apply.
- **2.1 writes a choice's allowed values into the new `facet_schemas` row.**
  Task 2.2 names this, but migration 6's check refuses a `choice` row with
  no allowed values, so 2.1 could not store `PNG` without it. 2.2 adds the
  comparison with the kept row and its tests.
- **A refused choice's reason leaves out the proposed text.** It reads
  `facet <name> is a choice of PNG, JPEG, and the text is none of them`, so
  an Operator's unbounded text never lands in the run's reason.
- **The header Operator also fails a PNG width or height above
  2,147,483,647.** Design decision 5 names this check; 3.2 tests it with
  `png_wider_or_taller_than_the_png_limit_fails`.
- **`CandidateReader::read` fills the whole buffer across windows.** The
  design has a read return what one window holds. zune-core reads a
  segment's 2-byte length with a single `read` call and takes any byte it
  did not get as zero, so a length that crossed a 64 KiB window boundary
  read as 0 and failed a valid JPEG. A read now returns fewer bytes only at
  the end of the candidate or after an error. The number of
  `read_candidate` calls is unchanged. Two tests in 3.3 guard this:
  `jpeg_whose_segment_lengths_cross_a_window_boundary_gives_its_width_and_height`
  and `jpeg_read_three_bytes_at_a_time_gives_the_same_answer`.
