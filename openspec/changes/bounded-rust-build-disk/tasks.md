## 2. Size-limited clean-up task

- [ ] 2.1 [medium] `sh server/scripts/target-clean.sh` measures the repo's `server/target/` as `du -sk` rounded up to whole MiB, deletes it when it is larger than `SIDEREAL_TARGET_LIMIT_MIB` MiB and keeps it at or under the limit, printing the size, the limit and which it did, with exit status 0; write the over-limit, under-limit and at-the-limit cases first in a new `server/scripts/target-clean-check.sh`, which builds each case in a `mktemp -d` copy of the repo layout, with 2 MiB fixture files written by `dd if=/dev/urandom` (design decision 5, test seam) (verify: `sh server/scripts/target-clean-check.sh`)
- [ ] 2.2 [easy] With no `server/target/` folder, the clean-up script prints that there is nothing to delete and exits with status 0 (verify: `sh server/scripts/target-clean-check.sh`)
- [ ] 2.3 [easy] With no `SIDEREAL_TARGET_LIMIT_MIB` set, the clean-up script uses a limit of 4096 MiB; with a value that is not a whole number, such as `2G`, it deletes nothing, names the variable in its error output and exits non-zero (verify: `sh server/scripts/target-clean-check.sh`)
- [ ] 2.4 [medium] The clean-up script touches only the repo's own `server/target`: it ignores `CARGO_TARGET_DIR`, never calls `cargo clean`, and deletes nothing and exits non-zero when `server/target` is a symbolic link, or when `server`, `server/target` or a folder inside `server/target` is a mount point, found by matching their physical paths (`cd -P` and `pwd -P`) against the lines that `mount` prints; it also refuses when `mount` fails or prints nothing, and when the physical path holds a space, tab, newline or backslash. The check script covers a stub `mount` first on `PATH` that lists `server/target`, one that lists `server/target/debug/cache`, one that lists `server`, one that exits non-zero, and a fixture under a folder whose name holds a space (design decision 5, step 5) (verify: `sh server/scripts/target-clean-check.sh`)
- [ ] 2.5 [easy] `mise run target-clean` runs `sh server/scripts/target-clean.sh` from a `[tasks.target-clean]` entry in `mise.toml` with a description, and neither the `check` task nor any task it runs runs it. One real run through mise, with an invalid limit, deletes nothing and shows that the task finds the script and passes the caller's `SIDEREAL_TARGET_LIMIT_MIB` through (design test seam) (verify: `mkdir -p .workspace && ! SIDEREAL_TARGET_LIMIT_MIB=not-a-number mise run target-clean 2>.workspace/target-clean-mise.err && grep -q SIDEREAL_TARGET_LIMIT_MIB .workspace/target-clean-mise.err && mise tasks info target-clean --json >/dev/null && test -n "$(mise tasks info target-clean --json | jq -r '.description // empty')" && test "$(mise tasks info target-clean --json | jq -r '.run[]')" = 'sh server/scripts/target-clean.sh' && for t in check check-compose check-openspec check-server check-web; do mise tasks info $t --json >/dev/null && ! mise tasks info $t --json | grep -q target-clean || exit 1; done`)
- [ ] 2.6 [easy] When `du` fails, the clean-up script deletes nothing and exits non-zero; when `rm -rf` fails, it exits non-zero and its error output says the folder may be partly deleted; the check script fakes each failure with a stub first on `PATH` (design decision 5, steps 6 and 7) (verify: `sh server/scripts/target-clean-check.sh`)
