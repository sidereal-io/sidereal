## Deviations Ledger

- **2.3: `OperationError` has two more variants than design decision 3 lists.** `UnknownOperator` and `UnknownVersion` answer a `RunRequest` that names no registered Operator or no stored Asset version. Core cannot record a run for either (the run row needs the Operator's registered version and a version that exists), so it records nothing and says why, instead of panicking. Upload always names a registered Operator and the version ingest just saved, so neither reaches the upload path.
- **3.2: a stopped upload task answers 503, not 500.** Design decision 5 says the handler answers a join error of the upload task "500 as other upload faults do". Every other upload fault answers 503 with `the upload could not be saved; try again later` (`UploadError::Failed`), so the join error uses that same answer and logs `upload failed: the upload task stopped`, as the design says.
- **3.5 was built before 3.4.** Task 3.4's tests read the Asset through `GET /api/assets/{id}` to find `"facets":[]`, and task 3.5 adds that route. Building 3.5 first lets 3.4's tests use the route as the task says. Each task still has its own commit.
