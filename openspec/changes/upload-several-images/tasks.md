## 1. The library screen uploads several files

All tasks in this section edit `web/src/Library.tsx` and
`web/src/Library.test.tsx`, so they run in order.

- [ ] 1.1 [medium] The picker takes several files and sends them in turn (design: "The picker takes several files" and "One loop sends the files in turn"). The file input has `multiple`; update the test "opens the file picker from one Upload button, for PNG and JPEG" to expect it. Picking `a.png`, `b.png` and `c.png` in one `change` event, with each upload answered by a `deferred` request, sends exactly one pending `POST /api/assets` at a time, in the order `a.png`, `b.png`, `c.png`, each body holding only its own `file` field. Copy the input's files into an array before clearing its value (verify: pnpm --dir web test -- Library.test.tsx)
- [ ] 1.2 [medium] Each chosen file has a line in a `<ul aria-label="Uploads">`, one `<li class="library-status">` per file in pick order, replacing the single `Upload` state with `lines` (design: "One list of lines replaces the single upload state"). With `a.png` saved, `b.png` pending and `c.png` not yet sent, the lines read `a.png was uploaded.`, `Uploading b.png…` and `c.png is waiting.`, in that order. A pick of only `nebula.png` that the server accepts keeps `nebula.png was uploaded.` beside the new image; update the test "shows the new image after success, without a page reload" for that line. A waiting `<b>m42</b>.png` shows as literal text with no `b` element. Add the `library-uploads` class to `web/src/Library.css`: no bullets, margin or padding, and a `var(--sr-spacing-8)` gap between lines. No new token (verify: pnpm --dir web test -- Library.test.tsx)
- [ ] 1.3 [easy] The next pick replaces the lines: after every file in a pick of `a.png` and `b.png` has an answer, picking `c.png` shows a line for `c.png` and no line for `a.png` or `b.png`. A cancelled picker (a `change` event with no files) sends nothing and keeps the last lines (verify: pnpm --dir web test -- Library.test.tsx)
- [ ] 1.4 [medium] One file's answer does not stop the others. Give `stubServer` a way to mark one turn in a list of answers as "no answer", which rejects like a network error (design: Test Seams). Picking `a.png`, `b.png`, `c.png` and `d.png`, answered 415, 409, no answer and 201, sends four upload requests in pick order and shows `a.png was not uploaded: only PNG and JPEG images are supported.`, `b.png is already in the library.`, `No answer came back for c.png. It is safe to upload it again: if it was saved, Sidereal will find it.` and `d.png was uploaded.`, in that order (verify: pnpm --dir web test -- Library.test.tsx)
- [ ] 1.5 [easy] The list loads again after each saved file and each lost answer, and not after a 409. Picking `a.png`, `b.png` and `c.png`, answered 201, 409 and 201, makes three `GET /api/assets` requests in all: one when the library opens, one after `a.png` and one after `c.png`. Picking `nebula.png` and `m31.jpg`, both accepted, shows both images by name (verify: pnpm --dir web test -- Library.test.tsx)
- [ ] 1.6 [medium] Upload waits for the whole pick (design: "Upload is disabled while any line is waiting or sending"). While the upload of `a.png` in a pick of `a.png` and `b.png` is pending, the Upload button is disabled, and a press or a new choice of `c.png` sends no request and adds no line. With answers 201 for `a.png` and 415 for `b.png`, the button is still disabled after `a.png`'s answer and is enabled once `b.png` has its answer. Update the test "shows the filename while pending and sends no second request" to match. The existing 409 and refusal tests, which pick one file, still find Upload enabled after the answer (verify: pnpm --dir web test -- Library.test.tsx)
- [ ] 1.7 [medium] Ending the session stops the files not yet sent. In a pick of `a.png`, `b.png` and `c.png`, a 401 answer for `a.png` calls `onSessionLost` once and sends no request for `b.png` or `c.png`. Unmounting the Library while `a.png` is pending, then answering it, sends no request for `b.png`, calls nothing and loads no list. Extend the test "ignores an upload that answers after the library is gone" or add one beside it (verify: pnpm --dir web test -- Library.test.tsx)
