- 2026-11-19, tasks 2.1 onward: the builder's session ran inside direnv's Nix shell, where `mise exec` found the Nix copies of `lets`, `gh` and Rust first (`lets --version` printed 0.7.0). Each mise check ran in a clean environment instead, with only mise and the system binaries on `PATH`. The checks themselves are unchanged. This is the "one route per shell" risk in design.md.
- 2026-11-19, task 2.4: the planned check ran `git check-ignore -q` on three paths, but `-q` accepts only one, so it exited 128 whatever `.gitignore` said. The check now runs `git check-ignore -q` once per path. It tests the same thing.
- 2026-11-19, task 3.1: the workflow sets `cache: false` on `jdx/mise-action`. The action's cache key hashes `mise.lock` but not `.mise/`, and a locked install over installed tools skips the sidecar check: with the sidecar deleted, `mise install --locked` passed over installed tools and failed from a fresh data directory. Without the cache, every run installs fresh, so a missing or edited sidecar fails as design Decision 5 says. The cost is a slower job, which runs only when a mise file changes. The pull request description should say this.
